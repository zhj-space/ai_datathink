> **计划类型**：部署实施计划（Planning Agent 结构化格式）
> **依据**：《实施执行计划 v2.0-r1》P0-B / Phase 1~4 +《设计方案 v3.2》4.1.2 / 4.2 / 4.3 / 6.3 / 第 9 章 ADR / 第 11 章验收标准
> **范围**：**仅单机版（POC）**——S1 底座 → S2 离线 → S3 实时 → S4 AI/试运行。三节点 M-Prod 不在本计划内。

## Summary

**要做什么**：在 1 台 24 vCPU / 96GB / 2TB NVMe 服务器上，用 Docker Compose 部署 AI 数据治理平台 POC，分四段递进交付：底座（6 容器）→ 离线治理（累积 13）→ 实时链路（累积 17）→ AI 能力（累积 **18**）。

**为什么这样分**：执行计划的任务按**周次**组织，但部署动作按**依赖**组织，两者不是一回事。例如 P0-B 第 2 周并列写了 PG、PgBouncer、OpenSearch，实际 PG→PgBouncer 有依赖、OpenSearch 可并行。本计划按依赖重排为 S1~S4，每段有独立可验证的准出门禁。

**高层架构**：单机单点，无容错。所有服务经 PgBouncer（6432）访问 PostgreSQL；OpenMetadata 为元数据唯一真理源；Flink CDC 直连源库（不部署 Kafka Connect）；Kafka 只承接日志事件与 `governance.alerts`。

**周期**：P0-B 2~3 周 + Phase 1 3~4 周 + Phase 2 3~4 周 + Phase 3+4 5~7 周 ≈ **11~14 周**。

**实测环境（2026-09-16）**：POC 服务器实测为 24 vCPU / 92GiB / **100G 单盘**（Ubuntu 26.04.1 LTS，无独立数据盘）。
不满足设计方案 4.1.2 中型档，也低于 4.1.3 最小测试环境的 200GB/300GB 磁盘门槛，**经人工决策按「最小测试环境 + 磁盘降级变体」执行**：
仅功能验证、不压测、不进生产；门禁①（fio/容量）**人工豁免**；参数按 4.1.3 收紧（OS heap 1g、Kafka 512m、Flink slots 2、Ollama 1.5b/3b）；
容器数口径取 **19**（cAdvisor 容器化，node_exporter/postgres_exporter 为宿主二进制）。详见《部署步骤_单机版》0.3。

**S1 执行状态（2026-09-16）**：S1 段已落地并通过可编程校验（7/7 healthy、`SHOW POOLS` 无 waiting、OpenSearch green、Prometheus 3/3 up、TLS 握手成功）。

**S1-8 与门禁②（2026-09-17）**：**RPO 口径已定 = ≤1h**（人工决策，执行计划 v2.0-r2 回填）；S1-8 备份链路已落地（小时级 PG 备份 + OpenSearch fs 快照 + cron + 出机 hook），首次恢复演练通过（PG 0.07s / OS 158ms，产物已清理）。
**门禁② 待 DBA 签字**，两条未闭环项须写进判读：① **出机介质未配置**（ADR-A4「每日出机」未完成）；② S1 阶段无业务数据，演练只证明机制可跑通。
证据见《AI数据治理平台_单机版_S1部署记录.md》§7，脚本见《AI数据治理平台_单机版_S1-8备份恢复脚本.md》。

**S1 安全面复查（2026-09-17）**：公网实测**仅 22/443 可达**（9100/9090/9200/6432 不可达，安全组实质承担过滤；宿主 `ufw` inactive 无第二道防线）；
SSH 存在**口令认证 + root 登录 + 24h 内 `Failed password` 37 次**（根因：cloud-init drop-in 覆盖主配置）。
**22 已由人工限源 IP；核查确认近 24h 成功登录仅本机来源（84 次）、非本机成功登录 0、未发现入侵**，且 OpenSSH 自带 `PerSourcePenalties` 已在挡爆破（原"无自动封禁"表述已更正）——
**残留待放行**：装公钥 / 关口令认证 / 轮换口令 / fail2ban。另有 5 个服务以 `:latest` 运行导致 S1 证据不可复现。详见 S1 记录 §3.7 与 §3.7.5。

**S3 前置（2026-09-18，人工授权"与 S2 并行"）**：**门禁④ 通行**（人工决定，原件归档待 SEC/DBA 补）后，先落地**不接触源库**的部分 ——
Kafka（KRaft 单节点、零端口发布、`governance.alerts` 2 分区/RF1/7d）、Flink（自建镜像含 CDC+Kafka 连接器、JM/TM healthy、slots=2、**冒烟消费通过 + Checkpoint 落数据盘**）、

**同批收口**：**门禁③ 人工判定通行**（原件签字待归档）；**FERNET_KEY 重做为自持 key**（元数据库重建 + 链路复建 + 判据复跑 0 命中）；**SSH 四件闭环**（公钥/关口令/轮换口令/fail2ban）；**node_exporter 收紧**；**新增配置出机**（`.env`+compose+`config/`，FERNET_KEY 自持后的必需项）。
**443 收敛（2026-09-18）**：人工确认**无固定企业 VPN/出口 IP** ⇒ 不做限源，改为**撤回暴露** —— **443 不再对外发布**（宿主无 443 监听），OM 改 `127.0.0.1:8585` 回环 + **SSH 隧道**（与 Superset/Airflow/Prometheus/门户同口径）；ETL 基址与门户链接同步改 ⇒ **对外仅剩 22（已限源）**。
**未做**：GA（S3-6，接口规格已出、**代码未写**）、CDC 作业（S3-5，依赖源库）、源库 exporter 与复制槽参数（依赖文件 B）；**镜像漏洞扫描未完成**（带宽/白名单受限）。详见《AI数据治理平台_单机版_S3前置部署记录.md》。

## Implementation Steps

> 每步含：**前置 / 动作 / 验收 / 失败处理 / 执行方**。执行方三档：`[A]` Agent 自主 · `[A+H]` Agent 起草+人工审核 · `[H]` 人工专属。来源：执行计划 RACI 与 Agent 边界章节。

### 阶段 S1：单机底座（P0-B，2~3 周）

#### S1-1 服务器初始化 ⬅ **门禁 ①**
- **前置**：服务器到位并通过验收（`nproc`=24 / `free -g`=96 / 系统盘 480G + 数据盘 2TB / **fio 顺序写 ≥1GB/s、4K 随机读 ≥100k IOPS**）
- **动作**：数据盘挂载至 `/data`（`mkfs.xfs` + `/etc/fstab`）；创建 8 个数据目录；内核参数 `vm.max_map_count=262144`、`vm.swappiness=1`、`ulimit -n 65535`
- **验收**：`df -h /data` 显示 2TB；`sysctl vm.max_map_count` = 262144
- **失败处理**：容量/性能不达标 → 拒收，重提采购
- **执行方**：`[H]`（到位/网络为人工专属；配置脚本 `[A]`）

#### S1-2 Docker 与 Compose 安装
- **动作**：`curl -fsSL https://get.docker.com | sh`；`systemctl enable --now docker`
- **验收**：`docker run --rm hello-world` 成功
- **执行方**：`[A]`

#### S1-3 三网隔离
- **动作**：创建 `frontend-net`（非 internal）、`backend-net`、`data-net`（后两者 `--internal`）
- **验收**：跨网容器 `ping` 不通；同网可通
- **执行方**：`[A]`

#### S1-4 部署 PostgreSQL + pgvector 与 PgBouncer
- **关键参数**：`pool_mode=transaction`、`default_pool_size=25`、PG `max_connections=80`、PG 内存 limit 4GB
- **验收**：`SHOW POOLS;` 可查询且 **waiting = 0**

- **执行方**：`[A]`

#### S1-6 Traefik 入口 + TLS
- **动作**：仅暴露 443（安全基线第 ④ 条）
- **验收**：`openssl s_client -connect <host>:443` 握手成功

#### S1-7 Prometheus + Alertmanager

#### S1-8 备份脚本 + 首次恢复演练 ⬅ **门禁 ②**

> **出机仍未闭环** ⇒ 门禁② 该项判据**继续挂账**（不视为已完成）；§9 的介质配置单保留待用。本地备份链与各级恢复演练照常。

#### S2-4 T-M0-1：OM × PgBouncer transaction 实测 ⬅ **门禁 ③**
- **动作**：OM 登录 → 浏览元数据 → 搜索（触发 OS 链路）→ 跑完整 ingestion → 打开血缘与质量页 → 收集两侧日志

- **执行方**：`[A+H]`；结论写入部署基线文档后 PgBouncer 配置定版

    volumes: ["/data/flink-checkpoint:/opt/flink/checkpoints"]
    networks: [data-net, backend-net]
    restart: unless-stopped
    deploy: { resources: { limits: { cpus: "1", memory: 2G } } }

  flink-taskmanager:
    image: ${FLINK_CDC_IMAGE}:${FLINK_CDC_DIGEST}
    command: taskmanager
    depends_on: [flink-jobmanager]
    environment:
      FLINK_PROPERTIES: |
        jobmanager.rpc.address: flink-jobmanager
        taskmanager.numberOfTaskSlots: 4
    volumes: ["/data/flink-checkpoint:/opt/flink/checkpoints"]
    networks: [data-net, backend-net]
    restart: unless-stopped
    deploy: { resources: { limits: { cpus: "3", memory: 6G } } }

  governance-agent:
    build: ./governance-agent
    depends_on: [kafka, pgbouncer, opa]
    networks: [backend-net, data-net]
    restart: unless-stopped
    deploy: { resources: { limits: { cpus: "2", memory: 4G } } }

  # ========== S4 AI 能力 ==========
  ollama:
    image: ollama/ollama:latest
    volumes: ["/data/ollama:/root/.ollama"]
    networks: [backend-net]
    restart: unless-stopped
    deploy: { resources: { limits: { cpus: "8", memory: "16G" } } }
