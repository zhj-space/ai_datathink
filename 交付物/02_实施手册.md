# AI 数据治理平台 · 实施手册（单机 POC）

> **文档版本**：v1.0（2026-09-21）
> **读者**：实施 / 集成 / 交付工程师（含接手本环境的人）
> **范围**：**单机 POC**（1 台服务器 + Docker Compose）。**生产形态（M-Prod 三节点 k3s）不在本手册范围**，触发式启动后另行发布。
> **边界（先看这条）**：**接生产库前，门禁④ 的两份书面文件必须已归档**（合规边界确认书 + 续接窗口签约定）——**硬约束，缺一不动生产库**。

## 2. 前置条件（部署前必须齐）

| # | 条件 | 判据 / 备注 |
|---|---|---|

## 3. 部署顺序（S1 → S4，每段都有判据）

> 原则：**门禁不过不进下一段**；每段的完整步骤见《部署步骤_单机版》，本节只给"做什么 + 怎么判达标"。

### S1 · 单机底座（第 1~3 周）

| 章节 | 做什么 | 判据 |
|---|---|---|
| S1-1 | 服务器验收 + 目录规划 | fio 达标 / 磁盘布局确认（**门禁①**） |
| S1-2~S1-6 | PostgreSQL+pgvector、PgBouncer、OpenSearch、Traefik、监控栈（Prometheus/Alertmanager/cAdvisor） | `docker compose ps` 全 healthy；`SHOW POOLS` 无 waiting；`_cluster/health` green |
| S1-7 | 告警规则载体 + postgres_exporter 抓取 | `rule_files` 生效、`/api/v1/rules` 非空、阈值来自源文档 |
| S1-8 | 备份体系（PG 每小时、OS 快照、配置归档、出机） | **逐库恢复演练通过**（**门禁②**：RPO ≤1h / RTO ≤4h） |

### S2 · 离线治理（第 4~7 周）

| 章节 | 做什么 | 判据 |
|---|---|---|
| S2-1~S2-3 | OpenMetadata 部署（连 PgBouncer）+ ingestion/Airflow + 门户入口 | OM healthy；**门禁③ T-M0-1**：过池后日志零 `prepared statement … does not exist` |
| S2-4 | 门禁③ 证据包（DBA+DE 判定） | 判定结论留档（**原件签字属人工**） |
| S2-5 | OPA 策略 / Presidio 规则 / gov_metrics 指标层 + 每小时 ETL | 决策用例 8/8；识别分层实测；`gov_metrics` 表与 ETL 运行记录可见 |
| S2-6 | Superset（**只读 gov_metrics**） | 看板可读；**反向连 OM 库被拒** |
| S2-7 | 治理门户（自研 Streamlit） | 五页可渲染、`portal_ro` 只读可达、Agent 未就绪时降级 |

### S3 · 实时链路（第 8~11 周）

| 章节 | 做什么 | 判据 |
|---|---|---|
| S3-1 | **门禁④**：合规边界 + 续接窗口签约定归档 | **两份原件归档后才允许接生产库** |
| S3-2~S3-3 | Kafka（KRaft 单节点）+ 自建 Flink 镜像（CDC 连接器**按 sha256 校验**） | healthy；镜像扫描无高危（flink 镜像扫描属**未执行项**） |
| S3-4 | **PG 复制槽保护三项验证** | 兜底生效 + 告警触发 + 删 slot 演练（走"作业下线 checklist"） |
| S3-5 | **D1 血缘**：GA 自研上报（ADR-A7）+ 每日对账 | 临时实体端到端 `applied` + OM 读回；对账 `drift` 可自愈；**零残留** |
| S3-6 | Governance Agent（告警落库增强 / 开放 API / 审批记录 / AI 编排） | `/health` 200；告警幂等落库；审批两条审计轨迹 |
| S3-7 | 端到端联调 | 端到端 P95 <30s；断流恢复 ≤ 续接窗口 1/3 |

### S4 · AI 能力与试运行（第 12~14 周）

| 章节 | 做什么 | 判据 |
|---|---|---|
| S4-1 | Ollama + 模型；**M0 第 6 项**首 token 实测 | **1.5b：冷启动 6.93s @1,819 tokens（达标）**；3b 不达标（需 GPU，属采购/评审） |
| S4-2 | pgvector + RAG（LangGraph 编排）+ **上下文预算 1800 tokens / num_ctx 4096** | 正例/负例/引用校验通过；`/chat` 回显预算口径 |
| S4-3 | CI/CD 血缘提示（≥1 仓库） | ⧗ **待目标仓库与 CI 信息** |
| S4-4 | 试运行、水位周报、容量基线、年度恢复演练 | 周报需**连续 14 天**数据（首个可判定 ≈ 2026-10-05） |

## 4. 四道门禁（阻断式，不通过不得进入下一段）

| # | 门禁 | 位置 | 判据 | 不通过怎么办 |
|---|---|---|---|---|
| ① | 服务器验收 | S1-1 前 | fio：顺序写 ≥1GB/s、4K 随机读 ≥100k IOPS | 拒收，重提采购 |
| ② | 备份可恢复 | S1-8 | RPO ≤1h / RTO ≤4h | 修脚本重验，**DBA 签字** |
| ③ | T-M0-1 OM×PgBouncer 兼容 | S2-4 | 日志零 `prepared statement …` / `transaction aborted` | **不自动降级**，DBA+DE 决策 session/直连 |
| ④ | 合规边界 + 续接窗口 | S3-1 | **两份书面文件归档** | **不动生产库** |

> **判读与签字属人工专属**：Agent 只能备齐证据，**不代签、不代判**（AGENTS §11）。

| 项 | 做法 |
|---|---|

## 6. 变更纪律（改配置 / 改规则 / 改镜像 / 改 UI）

### 6.1 通用四步
1. **改前快照**：把现行文件复制到 `/data/backup/config/<file>.<date>-pre-<主题>`（可回滚）
2. **改 + 校验**：改完立刻做**该组件特有的校验**（见下表）
3. **重跑验收**：按该章节的判据复跑，**留命令与输出**
4. **同步文档**：文档末尾"版本记录"追加一行（改了什么 / 怎么验的 / 还没做什么）

### 6.2 各类变更的专属校验

| 变更 | 必做 |
|---|---|
| 告警规则（`alerting/poc-alerts.yml`） | `promtool check rules` → `POST /-/reload` → 核对 `/api/v1/rules` `health=ok` → **真实触发验证**；**新增规则必须补 GA 的 `ADVICE` 模板**（否则日报摘要空） |
| 自建镜像（GA / 门户 / superset / flink） | **去 digest → build → 取新 image ID → 重钉 digest → 重启 → 重扫**（`trivy image --skip-db-update …`；本环境库更新极慢） |
| 门户 UI（`governance-portal/`） | 跑 `tools/` 四个校验（令牌/WCAG → mockup 结构 → HTML 解析 → AppTest）；**令牌只改两处**（`design/tokens.css` 与 `theme.py`），**不得放第三份 CSS** |
| OPA 策略 / Presidio 规则 | 改后**重启对应容器** + 重跑决策/识别用例 + 记录 sha256 |
| 数据库权限 | 变更后**回收 PgBouncer 池连接**（`RECONNECT`），否则变更不即时生效 |
| D1 血缘登记 | 登记目录 `/data/ai-governance/jobs/*.sql` 是**唯一真相源**；提交走 `submit_flink_job.sh`（干跑门禁→提交→上报） |

## 7. 常见故障与处置（本环境实测过的）

| 现象 | 根因 | 处置 |
|---|---|---|
| 容器级指标为空（cAdvisor 只有根 cgroup） | Docker 用 **containerd 镜像存储**，layerdb 无 `mount-id`；cAdvisor v0.45 建不出容器 | 本环境**已改用自采探针** `container_probe.sh`；cAdvisor 记 ⛔ 外部阻塞 |
| 告警"配好了却不报" | ① 自定义指标标签用了 `job`（被改名 `exported_job`）② textfile 采集某行非数字 ⇒ **整文件被拒收** ③ 跨源 `and` 未写 `on()` | 统一用 `task`/`container` + `name`；采集脚本**原子写 + 逐行自检**；跨源比较必须 `on()` |
| `increase(...)` 告警永不触发 | 计数器在**首次采集前**就已 >0（如容器启动即 OOM） | 用**累计计数**判据而不是窗口式 `increase` |
| `docker compose build` 报 `build tag cannot contain a digest` | compose 的 `image:` 带 `@sha256:` | **先摘 digest → 构建 → 再重钉** |
| SSH 会话里长任务被掐断 | helper 通道超时（≈600s） | 别在会话里放长 `sleep`；trivy 用 `--skip-db-update`；`nohup … &` 也会被带走 ⇒ 不用后台 |
| 脚本中文乱码 / 报"字符串未终结" | PS 5.1 按 ANSI(GBK) 读 `.ps1` | 含中文的 `.ps1` **必须存成 UTF-8 with BOM** |
| OM 建了采集任务但 Airflow 里没有 DAG | **只创建没部署**（OM 的"部署"是单独一步） | `POST /services/ingestionPipelines/deploy/{id}`（或 UI 的 Deploy）；触发报 `Dag id … not found in DagModel` 即此因 |
| OM 里看不到采集运行状态 | 状态未回写（`pipelineStatuses=0`） | 属**已知缺口**；以 Airflow 侧任务日志判成功/失败 |
| `airflow dags list-runs` 报 `Database migration required` | 容器内 CLI 与元数据库版本校验不过 | 仅影响 CLI；用 Airflow UI / REST API 查运行历史 |
