## 更新：移除冗余顶部导航（第四轮）

按你的要求，**删掉了设计稿顶部那排页面切换按钮**（① 首页 ② 系统状态 ③ 智能问答 ④ 治理指标 ⑤ 访问审计），切页**只保留左侧导航**。

**为什么它确实多余**：那排按钮是我为了让设计稿能"一页预览 5 个页面"而加的**查看器控件**，`app.py` 里根本没有它 —— 属于设计稿与产品不一致的地方。更糟的是它的顺序停留在**旧 IA**（系统状态还在第 2 位），跟修正后的导航顺序对不上，评审时会让人以为产品有两套导航。

**改动**：

| 项 | 变化 |
|---|---|
| `.ds-tabs` 按钮排 | **删除**（含 5 个 tab 按钮 + 数字键快捷键 + `←/→` 方向键逻辑） |
| 切页方式 | 改为**点左侧导航**（`<a href="#panel-xxx">` + JS），**与 `app.py` 的 `st.sidebar.radio` 行为一致** |
| 主题切换 | 移到说明区右上角（`margin-left:auto`），它是评审辅助控件，不是产品功能 |

## 更新：IA 调整（第三轮 —— bug 修复 + 导航重排）

按你的两条要求完成：

### 1. 修掉侧栏重复项（真 bug，根因在 mockup.html）

截图里导航列表下方那个**被单独框起的「访问审计与审批（场景 E）」**，根因是 **HTML 结构非法**：

```html
        </ul>                          <!-- ← <ul> 在这里就闭合了 -->
          <li class="gv-nav__item"><a href="#">访问审计与审批（场景 E）</a></li>   <!-- 孤儿 <li> -->
        </ul>                          <!-- ← 多余的孤立 </ul> -->
```

`<ul>` 提前闭合后，紧随的 `<li>` 成了 `<ul>` 之外的**孤儿元素**（还多了一个孤立 `</ul>`）。浏览器解析器会忽略多余 `</ul>`，把孤儿 `<li>` 提升到 `<nav>` 下渲染 —— 于是它在导航列表之外**独立成行**，正是你标注的那一项。

**同批查出的连带缺陷**（同一批 nav 手工复制时漏改）：

| panel | 原问题 |
|---|---|
| `panel-home` | 孤儿 `<li>` + 多余 `</ul>`（本次 bug 根因） |
| `panel-metrics` | nav 只有 4 项、**顺序错乱**、链接全是 `href="#"` 死链 |
| `panel-chat` | nav 只有 4 项、链接全是 `href="#"` 死链 |
| `panel-audit` | nav 只有 4 项、链接全是 `href="#"` 死链 |

**修复**：5 份 nav 统一为**同构** —— 5 项、正确的 `#panel-*` 锚点、各自的 `aria-current="page"`、顺序符合 IA 基准。

**防线**：新增 `tools/check_mockup_nav.py`（当时 39 项，现 42 项），含专门的**孤儿 `<li>` 检测**；回归脚本也内联了同一批结构断言。这类缺陷现在会被 CI 拦住。

### 2. 「系统状态」移到左侧最后

`status` 是**运维诊断页**，而 `chat`/`metrics`/`audit` 是业务用户的日常主路径。把它插在导航第 2 位，业务用户每次扫读导航都要先越过一个与自己无关的页面。移到末尾后，导航遵循「**先业务、后运维**」的阅读顺序。

**左侧导航 5 项（新顺序）**：

| # | 导航项 | slug | 变化 |
|---|---|---|---|
| 1 | 首页 / 能力入口 | `home` | — |
| 2 | 智能问答（场景 D） | `chat` | ↑ 上移 |
| 3 | 治理指标 | `metrics` | ↑ 上移 |
| 4 | 访问审计与审批（场景 E） | `audit` | ↑ 上移 |
| 5 | **系统状态（运维视角）** | `status` | ↓ **移至末尾** |

首页入口网格的站内模块卡**同步调序**（问答在前、状态在后）—— 入口卡顺序与导航顺序不一致会制造"两套 IA"的错觉。

**首页「能力入口」统一入口网格**（2 个站内模块卡 + 5 个外部深链卡）：

```
┌────────────────────────┬────────────────────────┐
│ ▎💬 智能问答      [可用] │ ▎🧭 系统状态   [全部正常] │  ← 站内模块（左竖条 + ›）
│   元数据血缘问答          │   下游服务健康度          │
├────────────────────────┼────────────────────────┤
│ 📚 资产目录/血缘  [需隧道] │ 📊 治理 BI 看板   [需隧道] │  ← 外部深链（↗ 新窗口）
├────────────────────────┼────────────────────────┤
│ 🔁 批处理作业     [需隧道] │ 📈 采集与告警监控  [需隧道] │
├────────────────────────┼────────────────────────┤
│ 🔔 告警路由       [需隧道] │                        │
└────────────────────────┴────────────────────────┘
```

**为什么给站内模块做视觉变体？** 两类卡片长得一样的话，用户点下去才知道会不会离开本站 —— 很差的心智模型。所以站内模块用**左侧 3px 竖条 + `›` 箭头**，外部深链用 **`↗` 箭头 + 新窗口**，形成**形状 + 颜色双通道**区分（不依赖单一颜色通道，符合 WCAG 1.4.1）。站内卡还带**实时状态徽标**，用户不进页面就知道 Agent 是否就绪。

**收益**：两者各有稳定深链（`?page=status` / `?page=chat`），可被运行手册、告警通知、外部文档直接引用；首页回归纯粹的总览职责。深链按 slug 索引，与导航顺序无关，**顺序调整不影响任何已有深链**。

## 关键设计决策（都带依据，非审美偏好）

**1. 环形图强制三联** —— 中心语义标签 + 环体 + **一一对应的图例**。
原稿 `1` 旁边没有任何文字说明它是什么，读者只能猜。现在中心写「已登记资产」，右侧图例列出「颜色 → 标签 → 数值 → 占比」。

**2. KPI 卡强制带口径脚注** —— 原稿 `17/18/19` 最大的问题是口径不明。现在每个数字下方写明「这个数怎么算的」，防止数字随口径漂移而无人察觉。

**3. `—` 与 `0` 严格区分** —— `asset_coverage_pct` 在接入业务源前为 NULL。原设计很容易显示成 `0%`，那是**错误信息**。现在显示 `—` 并在脚注注明「不适用（NULL ≠ 零）」。

**4. 降级用橙色而非红色** —— Agent 未就绪是 fail-safe 的**设计内行为**，不是故障。渲染成红色会让运维误判系统挂了。

**5. 状态三通道表达** —— 每个状态同时用「语义色 + 小圆点 + 文案」，色觉障碍用户仍可辨读（WCAG 1.4.1）。

**6. 空状态三段式** —— 「缺什么 / 数据从哪来 / 现在去哪看」，即使没数据用户也知道下一步。

**7. 正文基准 14px 而非 16px** —— 治理后台是信息密度优先场景，14px 配 1.7 行高是同类产品（Grafana/Superset/OpenMetadata）通行做法。

## 过程中修正的四个真问题

**① 弱化文字对比度不达标**（由校验脚本捕捉，非目视判断）
初版 `#6b7c8c` 白底只有 **4.30:1**，未达 AA 要求的 4.5:1。修正为 `#5f6f7e`（**5.17:1**）；原色降级为 `--color-border-strong`（非文字边界只需 3:1，4.30:1 合规）。

**② 入口卡片元数据全部失配**（重构中引入的真 bug）
我按短名 `"OpenMetadata"` 建索引，但 `config.ENTRY_LINKS` 的实际 key 是 `"资产目录 / 血缘 / 质量（OpenMetadata）"` 这样的长标题 → 五个入口全部静默回落到兜底图标与描述。已改为子串匹配。

**③ mockup 侧栏出现重复导航项**（你截图报的那个，HTML 结构非法）
`panel-home` 的 `<ul class="gv-nav__list">` 提前闭合，其后的 `<li>` 成为**孤儿元素**（并伴随一个多余 `</ul>`）。浏览器解析器忽略多余 `</ul>`、把孤儿 `<li>` 提升渲染 → 它在导航列表之外独立成行。同批还查出另外 3 份 nav 缺项 + 全是 `href="#"` 死链。已全部统一为同构，并新增 `check_mockup_nav.py` 做**孤儿 `<li>` 专项检测**兜底。

**④ `.sr-only` 用了但从未定义**（最终稿校对时发现，第五轮）
表格的 `<caption class="sr-only">` 本应只对屏幕阅读器可见，但 `.sr-only` 在 CSS 里根本不存在 → 这个标题被**可见渲染**，与视觉标题重复。这类缺陷**浏览器不报错、正则看不出、目视容易忽略**。已补定义，并新增 N9 组「类名完整性」断言。

教训：mockup 每个 panel 复制一份 nav（为了每页可独立预览），代价是 5 份需手工保持同构。**用校验替代抽象** —— 对无构建步骤的静态稿是更划算的选择。
