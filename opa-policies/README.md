# OPA 策略（策略即代码）

> **定位**：本目录是**策略即代码（Policy as Code）**的版本化落点（设计方案 2.1 组件表：OPA「策略即代码、访问控制/审批规则」；设计方案"配置即代码"纪律）。
> **部署位置**：服务器 `/data/ai-governance/config/opa/policies/`，以只读方式挂载进 `opa` 容器（`/policies`）。
> **权威文档**：《AI数据治理平台_单机版_S2-5OPA策略与部署.md》（含本目录文件的原文与部署/验证记录）。

| 文件 | 包 | 用途 |
|---|---|---|
| `access_audit.rego` | `governance.access_audit` | **事后审计 + 主动告警**决策：给定访问事件，判定是否告警与级别（POC 场景 E / ADR-A3） |
| `authz.rego` | `governance.authz` | 授权决策骨架（**POC 不用于在线拦截**），承载 fail-closed 语义 |
| `data.json` | `data.governance.config` | 策略参数：PII 标签清单、高风险操作清单、批量阈值、非工作时段、告警通道 |

**纪律与状态**：

1. **fail-closed**：默认拒绝；条件不全即拒绝；**OPA 不可用时调用方必须按"拒绝/告警"处理**，不得放行（`authz.rego` 中的 `fail_closed_contract` 明确该约定）。
2. **POC 定位**：只做事后审计 + 主动告警，**不做事前拦截**（设计方案场景 E / ADR-A3）；本目录的 `authz.rego` 因此不接入在线链路。
3. **审核状态**：**待人工审核**（AGENTS §11：OPA 策略与规则阈值属"起草 + 人工审核"档）。`data.json` 中的阈值（批量行数阈值、非工作时段）为**工程经验取值，须业务/安全方确认**。
4. **变更流程**：修改本目录文件后须同步《…S2-5OPA策略与部署.md》的版本记录，并重新执行部署验证（策略编译自检 + 决策用例）。
