# AI 数据治理平台 POC 服务器采购需求说明

> **依据**：《AI数据治理平台设计方案》v3.2（4.1.2 单机容量规划/6.3 部署）+《实施执行计划》v2.0-r1（P0-A 采购与外部依赖）。
> **采购结论（一句话）**：本次仅采购 **1 台 POC 服务器（24 vCPU / 96GB / 2TB NVMe）**；生产 3 节点**不在本单范围**，须待 M-Prod 触发条件满足后另立采购（见第 8 节）。
> **到位时点**：P0-B（单机底座搭建）启动前。晚到位 = 项目关键路径顺延。

---

## 1. 三种采购路径对比（先选路径，再提规格）

| 路径 | 预估成本量级 | 优点 | 风险/限制 | 建议 |
|---|---|---|---|---|
| **A. 闲置服务器复用** | 0 元 | 零成本、最快到位 | 需满足规格与磁盘寿命；可能与其他用途冲突 | **第一顺位**：先按第 4.3 节验收清单筛一遍企业闲置资源 |
| **B. 云主机（包月）** | 中（按月、可退） | 分钟级到位、无硬件运维、POC 结束可释放 | 磁盘 IOPS 依赖云盘规格（普通云盘会拖垮 PG/OpenSearch）；数据出云有带宽成本 | **第二顺位**：若选云，必须选**本地 NVMe / 高 IOPS 型**云盘（见 3.2） |
| **C. 全新物理机** | 高（一次性） | 性能与 IO 确定、长期摊薄成本 | 采购周期长（2~6 周）；POC 失败则闲置 | 若 POC 成功概率高且生产节点可与本台复用，则值得 |

> 📌 建议：**A 筛完 → B 过渡 → 视 POC 结论决定 C**。预算紧的前提下，不要为 POC 直接买物理机，除非采购周期可接受且该机器未来可转为生产节点或测试机。

---

## 2. 配置依据（为什么是这台）

- **v3.2 · 4.1.2 单机中型档**：24 vCPU / 96GB / 2TB NVMe（离线+实时完整链路，含 Flink+Superset），对应 POC 需要的实时治理场景
- **容器内存预算校验**：全部容器内存 limits 之和约 51~59GB（PG 4G、OpenSearch 8G、OM 4+4G、Ollama 8~16G、Flink 6~8G、Kafka 4G、Superset/Prometheus/GA 等合计 ~13G），96G × 70% ≈ 67G 上限，留出 OS 与页缓存余量 ✅
- **磁盘构成**：系统盘 480G（OS + Docker）+ 数据盘 2TB（PG / OpenSearch / Kafka / Flink Checkpoint 全部容器数据卷），POC 期数据量 <10GB/天、保留 7 天，2TB 充足

## 3. 规格单

### 3.1 物理机版（路径 C）

| 部件 | 要求 | 说明 |
|---|---|---|
| CPU | ≥24 核（如 2×12C），主频 ≥2.4GHz，支持 AVX2（最好 AVX-512） | pgvector 向量计算与 Ollama CPU 推理都受益于 AVX |
| 内存 | 96GB（建议 6×16GB，保留插槽可扩至 192GB） | 对应单机大型档的升级空间 |
| 系统盘 | 2×480GB SSD，RAID1 | 仅 OS + Docker，RAID1 保启动可靠性 |
| 数据盘 | **2TB NVMe SSD（必须是 NVMe，不接受 SATA SSD）** | PG/OpenSearch/Flink Checkpoint 三个 IO 敏感组件；顺序写 ≥1GB/s |
| 备份位 | 预留 1 个盘位（可选 4TB SATA HDD 做每日出机备份的本地缓存） | 最终备份目的地由基础设施盘点结果决定（企业 NFS/对象存储/异地） |
| 网卡 | 双千兆起步，万兆更好 | 一路到源业务库（CDC），一路到企业 Kafka/SSO |
| 远程管理 | IPMI/iDRAC/iLO 带外管理口 | INFRA 远程运维刚需 |
| 电源 | 单电源可接受（POC）；机房要求则双电源 | — |
| 质保 | ≥3 年，次日上门（NBD） | — |
| 操作系统 | Ubuntu 22.04 LTS 或 Rocky Linux 9（装 Docker） | 不预装其他软件，到货裸机交付 |

### 3.2 云主机版（路径 B）

| 项 | 要求 |
|---|---|
| 规格 | 24 vCPU / 96GB 通用或计算型 |
| 系统盘 | 480GB 高性能云盘 |
| **数据盘** | 2TB **本地 NVMe 型或高 IOPS 云盘（ESSD PL2 及以上档位）**——普通云盘的 IOPS 会拖垮 PG/OpenSearch，**这是云路径最常见的坑** |
| 网络 | 与源业务库、企业 Kafka/SSO **同 VPC 或已打通**（跨 VPC 延迟会伤实时链路） |
| 计费 | 包月，POC 结束可释放/降配 |

### 3.3 闲置复用验收清单（路径 A）

逐项核对，任一不满足则放弃该机器：

- [ ] CPU ≥24 核且支持 AVX2（`lscpu | grep avx2`）
- [ ] 内存 ≥96GB（`free -g`）
- [ ] 数据盘 ≥2TB 且为 NVMe/SSD（`lsblk -d -o NAME,ROTA,SIZE`，ROTA=0；HDD 不合格）
- [ ] 磁盘健康（`smartctl -a` 无重映射扇区增长、寿命余量 >70%）
- [ ] 可重装系统/分配独立卷，无残留占用
- [ ] 网络可达源业务库、企业 Kafka/SSO 所在网络
- [ ] 明确该机器 8~14 周（POC 周期）内不被回收

## 4. 到货验收标准（可编程验收，INFRA 执行）

| 验收项 | 方法 | 通过标准 |
|---|---|---|
| CPU/内存/磁盘容量 | `nproc` / `free -g` / `lsblk` | 24 核 / 96GB / 系统盘 480G + 数据盘 2TB |
| 数据盘性能 | `fio` 顺序写 1M / 随机读 4K | 顺序写 ≥1GB/s；4K 随机读 ≥100k IOPS（防"NVMe"变 SATA/网络盘） |
| 网络连通 | 到源库/Kafka/SSO 目标端口 `nc -zv` | 全通（需网络策略先放行） |
| 带外管理 | IPMI 登录 | 可登录 |

## 5. 本单之外不采购的（写进申请，防超范围）

- ❌ 生产 3 节点服务器（触发条件未满足：业务 SLA / 水位>70% 两周 / 规模 / 合规，见执行计划 v2.0-r1 第 1 章）
- ❌ GPU（仅当 M0 实测 Ollama CPU 推理首 token <10s 不达标时，Phase 3 再评估）
- ❌ 额外网络设备/交换机（复用机房现有网络）

## 6. 采购申请单要素（直接抄）

> 用途：AI 数据治理平台 POC 试点（单机 Docker Compose 部署，约 17 个容器）
> 数量：1 台（规格见 3.1/3.2）
> 到位时点：P0-B 启动前（关键路径阻塞项）
> 责任人：INFRA 提需求、PM 走流程
> 验收：按第 4 节标准，验收不通过拒收

## 7. 到位后的衔接

服务器到位 = P0-B 第 1 周开工信号（OS/网络/数据盘配置 → Docker/Compose → PG+PgBouncer+OpenSearch → 监控/Traefik/备份脚本），详见《实施执行计划》v2.0-r1 P0-B 章节。

## 8. 生产 3 节点预告（仅备忘，不采购）

M-Prod 触发后按 **ADR-A8 公式**测算：`每节点 = PG全量×1.3 + 日增×Kafka保留天数 + OS索引(<100GB) + Checkpoint保留量 + 系统盘480G + 20% 余量`；短保留（1~3 天）4TB/节点（预算紧推荐）或长保留（7 天）8TB/节点；三台规格一致。届时随附：kube-vip/MetalLB/CNPG/SeaweedFS 的部署需求（均软件层，无额外硬件）。
